# UI Guidelines

## Overall Visual Direction
The UI should feel:
- modern
- clean
- bold enough to feel energetic
- simple enough for fast understanding
- social and slightly playful

This is not a banking dashboard.
This is also not a childish game UI.

The sweet spot is:
clean product UI + fun viral platform energy

---

## Design Keywords
- clean
- friendly
- fast
- rewarding
- scrollable
- social
- mobile-first
- easy to scan

---

## Core UI Patterns
Use these patterns consistently:
- card-based layouts
- rounded corners
- clear CTA buttons
- visible reward amounts
- badges for category/status
- light layering and spacing
- sections with strong titles

---

## Important Elements
The following elements should visually stand out:
- reward amount
- accept / create actions
- dare category
- dare status
- upload proof action

---

## Feed Design Principles
The dare feed should:
- feel immediately understandable
- make each dare card easy to scan
- show reward clearly
- show category clearly
- have obvious action buttons
- work well on mobile

Each dare card may include:
- title
- short description
- reward amount
- category badge
- difficulty or type
- user action button

---

## Landing Page Principles
The landing page should quickly answer:
1. what this product is
2. why it is fun
3. how it works
4. what the user should do next

Suggested sections:
- hero
- how it works
- featured dares
- safe fun categories
- CTA section

---

## Create Dare Page Principles
The create page should feel:
- easy
- guided
- safe
- not overwhelming

Form should be broken into clear sections.
Avoid giant intimidating forms.

Possible sections:
- basic info
- category
- reward
- proof requirements
- review/submit

---

## Profile Page Principles
Profile page should show:
- user identity
- stats
- created dares
- completed dares
- earnings
- recent activity

Keep it simple and card-based.

---

## Wallet Page Principles
Wallet page should clearly show:
- current balance
- pending balance
- transaction history
- payout or withdrawal CTA placeholder

Even if backend is not connected yet, the layout should already support this.

---

## Tailwind Styling Direction
Use Tailwind for layout and styling.
Prefer:
- balanced spacing
- readable font sizes
- clear states
- simple shadows/borders where needed
- strong CTA contrast

Avoid:
- excessive gradients everywhere
- heavy glassmorphism
- overly complex animation
- cramped cards
- too many colors at once

---

## Responsiveness
Must be mobile-friendly from the start.

Priorities:
- stacked layout on mobile
- readable cards
- buttons large enough to tap
- forms easy to use on small screens

---

## Reusability Rules
When similar UI appears more than once, prefer reusable components.
Good candidates:
- button
- card shell
- badge
- section heading
- page header
- empty state
- stat box

---

## AI Instructions for UI Work
When building UI:
- keep visuals consistent
- do not overcomplicate
- prefer clean MVP components
- keep code readable
- do not introduce unnecessary dependencies
